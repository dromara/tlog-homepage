TLog 2.0

一个 TraceId，串起每一行日志。

轻量级分布式日志追踪。跨服务、跨线程、跨网关、跨消息队列，
让散落各处的日志，回到同一条请求链路。

开始接入 2.0GitHub
01 · FOLLOW ONE REQUEST

服务可以分散，
线索始终相连。

  1. 01
    请求进入

    入口没有上游 TraceId，TLog 生成一个，并以根 span 0 标记这一层。

  2. 02
    调用库存服务

    RestTemplate 出站时自动带上 TraceId，下游入口拿到子 span 0.1。

  3. 03
    调用支付服务

    同一层再次出站，序号自增为 0.2。调用方自己的日志仍然是 0。

  4. 04
    继续向下

    支付服务以 0.2 为父，向风控发起调用，层级延伸为 0.2.1。

  5. 05
    切换线程

    异步线程继承当前上下文，日志依旧是同一个 TraceId、同一个 span。

  6. 06
    发出消息

    KafkaTemplate 把 TraceId 写进消息 header，通知服务在 @KafkaListener 里拿到子 span 0.3。

  7. 07
    一次搜索，全部找回

    在任何日志平台里搜索这个 TraceId，整条链路按调用顺序排好。

一个坐标tlog-web-spring-boot-starter2.0.0
  • Boot 2Spring 5javax.servletJDK 8+
  • Boot 3Spring 6jakarta.servletJDK 17+
  • Boot 4Spring 7jakarta.servletJDK 17+

一套产物，三代 Spring Boot。

按 Spring 代际自动注册 javax 或 jakarta 入口。保留熟悉的坐标，不需要 -jakarta 后缀。

只标记日志，保持简单。

不另建存储，不接管日志平台。让已有日志多一条可检索的线索。

跨线程，也有迹可循。

Spring 执行器、Reactor Context 与 MDC，传递同一个请求上下文。
