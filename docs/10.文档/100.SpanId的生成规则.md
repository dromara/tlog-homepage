# SpanId的生成规则

默认标签为 `<$spanId><$traceId>`。traceId 用来关联同一个请求，spanId 表示当前节点在调用树中的位置。

没有上游 spanId 时，入口使用根 span `0`。每次通过 TLog 传播器向下游发起调用，会生成“当前 span + 自增序号”的子 span。

| 调用 | 本端当前 span | 写给下游的 span | 下游入口使用的 span |
| --- | --- | --- | --- |
| A → B | `0` | `0.1` | `0.1` |
| A → C | `0` | `0.2` | `0.2` |
| A → D | `0` | `0.3` | `0.3` |
| C → E | `0.2` | `0.2.1` | `0.2.1` |
| C → F | `0.2` | `0.2.2` | `0.2.2` |

**发起调用不会把 A 自己的当前 span 改成子 span。** A 在调用前后的普通业务日志仍是 `0`，B 的入口日志才是 `0.1`。

```text
<0><demo-request-001> A 调用 B
<0.1><demo-request-001> B 处理请求
<0><demo-request-001> A 收到 B 的结果
```

## 异步与并发

同一请求通过受支持的传播方式切换线程时，保留当前 span，并共享其原子序号计数器。不同并发调用会获得不同子序号，但序号不承诺与业务完成顺序一致。请求结束后会清理当前 span 和计数器。

普通 WebFlux 入口保留原始请求头，首个 WebClient 出站为 `0.1`。Gateway 的转发会生成子 span，因此再经过下游服务继续调用时，层级可能为 `0.1.1`。

这不是 W3C 的 16 位十六进制 span-id，也不表示 TLog 会自动导出整棵追踪树。只覆盖已接入并正确传播的调用边；完整链路检索仍由日志系统承担。
