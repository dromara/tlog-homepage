# TLog能解决什么痛点

一次请求经过多个服务时，应用日志往往分散在不同文件或日志平台中。TLog 在入口建立 traceId，在适配的 HTTP、RPC、消息（Kafka、RabbitMQ 等）和任务调用中传递上下文，让同一条链路的日志可以用同一个 ID 检索。

例如，订单服务调用库存服务时，两边可以输出：

```text
<0><demo-request-001> 开始处理订单
<0.1><demo-request-001> 检查库存
```

其中 traceId 关联请求，spanId 表示调用层级。TLog 还可以把上游应用、主机、IP 和方法级业务标签放入日志。

## 与现有日志平台配合

TLog 不负责采集、存储、检索或展示日志。它把标签写入已有日志；日志文件、集中采集系统或云日志服务继续承担后续处理。接入后应同时检查应用实际输出和日志平台的字段提取规则。

已有 OpenTelemetry 或其它追踪系统的项目也可使用 TLog。2.0 可以从合法的 W3C `traceparent` 入站头复用 traceId，方便关联检索；它不提供完整的 W3C 出站传播、采样决策或 span 导出。

## 从哪里开始

Spring Boot 项目先看[快速开始](/guide/quick-start)，已有 1.x 项目先看[升级指南](/guide/upgrade)。TLog 2.0 仅通过日志配置文件接入，原来的 javaagent 和字节码增强方式已移除。

性能取决于日志量、线程模型和上下文传播路径。当前文档不承诺固定损耗比例；实际验证范围见[兼容性与验收](/guide/compatibility)。
