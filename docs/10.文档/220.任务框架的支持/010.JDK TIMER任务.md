# JDK TIMER任务

`tlog-task:2.0.0` 中的 `TLogTimerTask` 可以替换 JDK `TimerTask`。每次 `run()` 都建立新的 TLog 上下文，再调用你的 `runTask()`，最后清理。

```java
import com.yomahub.tlog.task.jdk.TLogTimerTask;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import java.util.Timer;

Logger log = LoggerFactory.getLogger("timer-demo");
Timer timer = new Timer("demo-timer", true);
timer.scheduleAtFixedRate(new TLogTimerTask() {
    @Override
    public void runTask() {
        log.info("执行一次定时任务");
    }
}, 100L, 1000L);

// 在应用关闭时调用 timer.cancel()。
```

重写 `runTask()`，不要覆盖负责建立和清理上下文的 `run()`。TLog 的 finally 清理不会改变 JDK Timer 的异常规则：未处理的业务异常仍可能终止 Timer 线程。

## 与 ScheduledExecutorService 的区别

```java
// 在已有 TLog 上下文的请求或任务中提交。
ScheduledExecutorService scheduler = TLogExecutors.wrap(
        Executors.newScheduledThreadPool(2));
scheduler.schedule(() -> log.info("执行延迟任务"), 1, TimeUnit.SECONDS);
// 应用关闭时调用 scheduler.shutdown()。
```

`TLogExecutors` 位于 `com.yomahub.tlog.core.thread`，JDK 类型位于 `java.util.concurrent`。包装器传播的是**提交时**的上下文；周期任务重复使用该捕获值。`TLogTimerTask` 则在每轮入口创建新 trace，两者用途不同。

完整示例见示例工程 `tlog-example-task-jdk`，运行方法见[可运行示例](/guide/examples)。
