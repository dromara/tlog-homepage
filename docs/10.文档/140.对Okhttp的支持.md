# 对Okhttp的支持

在 OkHttp 的应用拦截器链中安装 `TLogOkHttpInterceptor`，即可传播当前 TLog 上下文。它不依赖 Spring，也不会自动为没有上下文的任意调用创建 trace。

## 依赖与接入

```xml
<dependency>
    <groupId>com.yomahub</groupId>
    <artifactId>tlog-okhttp</artifactId>
    <version>2.0.0</version>
</dependency>
```

应用自行声明 `com.squareup.okhttp3:okhttp` 并选择与运行 JDK 相符的版本。TLog 对 OkHttp 使用 provided/optional，不把客户端及其运行依赖强加给使用者。当前 2.0 产物需[本地构建安装](/guide/compatibility)。

```java
import com.yomahub.tlog.okhttp.TLogOkHttpInterceptor;
import okhttp3.OkHttpClient;
import okhttp3.Request;
import okhttp3.Response;

OkHttpClient client = new OkHttpClient.Builder()
        .addInterceptor(new TLogOkHttpInterceptor())
        .build();

Request request = new Request.Builder()
        .url("http://127.0.0.1:18081/api/context")
        .build();
try (Response response = client.newCall(request).execute()) {
    if (!response.isSuccessful() || response.body() == null) {
        throw new IllegalStateException("HTTP status: " + response.code());
    }
    System.out.println(response.body().string());
}
```

复用 `OkHttpClient`，每次读取后关闭 `Response`。上例使用 `addInterceptor`，不要再同时安装一次相同的网络拦截器，以免一次调用分配多次子 span。

Spring Boot 的 `tlog.http-client.enabled` 控制 RestTemplate、WebClient.Builder、RestClient.Builder 的自动装饰，不替你安装或移除 OkHttp 的手工拦截器。跨工作线程调用还需使用[线程池包装](/pages/57ac1c/#异步调用)或应用已有的 TLog 自动装饰执行器。

## 异步调用

可以把同步 `execute()` 放入包装后的执行器，明确在提交时捕获上下文：

```java
ExecutorService pool = TLogExecutors.wrap(Executors.newFixedThreadPool(4));
try {
    pool.submit(() -> {
        try (Response response = client.newCall(request).execute()) {
            System.out.println(response.code());
        }
        return null;
    }).get();
} finally {
    pool.shutdown();
}
```

此处的 `TLogExecutors` 位于 `com.yomahub.tlog.core.thread`；JDK 执行器类型位于 `java.util.concurrent`。不要把该示例当作 OkHttp 自有 Dispatcher 或任意 callback 都已自动传播的承诺。实际验证覆盖的客户端版本和路径见[示例验收](/guide/examples)。
