# 对SpringCloud Gateway的支持

在响应式 Spring Cloud Gateway 服务中引入 `tlog-gateway-spring-boot-starter:2.0.0`，TLog 会注册自己的 `GlobalFilter`。不需要为了网关再叠加 `tlog-web-spring-boot-starter` 或手工创建 TLog Filter。

```xml
<dependency>
    <groupId>com.yomahub</groupId>
    <artifactId>tlog-gateway-spring-boot-starter</artifactId>
    <version>2.0.0</version>
</dependency>
```

应用仍需提供与 Boot 版本匹配的 Spring Cloud Gateway 依赖。这里指基于 WebFlux 的 `GlobalFilter` 接入，不把它描述为 Spring Cloud Gateway Server MVC 的适配。

## 上下文与下游调用

网关在入口建立或沿用 traceId，为转发请求写入子 span。后续 WebFlux 服务再通过 WebClient 调用下游时，典型链路为：

```text
Gateway                 WebFlux                  HTTP 下游
trace = 同一个值        trace = 同一个值         trace = 同一个值
span  = 0               span  = 0.1              span  = 0.1.1
```

普通 WebFlux 服务不会为了建立入口上下文而改写收到的请求头；网关的实际转发才会注入子 span。无需在路由代码里手工拷贝 TLog 头。

```yaml
tlog:
  enabled: true
  web:
    enabled: true
    response-header: true
```

总开关、Web 开关和响应头回写开关都适用于 Gateway。应用名可选，未配置 `spring.application.name` 时使用 `NONE`。
