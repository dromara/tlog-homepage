# 对RestTemplate的支持

TLog 2.0 会为 Spring 容器里的 `RestTemplate` Bean 自动添加 `TLogRestTemplateInterceptor`，保留已有拦截器，并避免重复安装同一 TLog 拦截器。

## Spring Boot 自动接入

使用包含 `tlog-rest-template` 的 TLog starter，例如 `tlog-web-spring-boot-starter:2.0.0`，再声明客户端 Bean：

```java
@Bean
public RestTemplate restTemplate() {
    return new RestTemplate();
}
```

通过容器注入这个 Bean 后，调用 `getForObject`、`exchange` 等方法即可传播当前上下文。下列开关默认开启：

```yaml
tlog:
  http-client:
    enabled: true
```

此开关控制自动装饰。它不会删除用户在代码中手工添加的拦截器，也不会创建所有 HTTP 客户端。对于 Bean，即使你在 `@Bean` 方法里手工加了 TLog 拦截器也不会重复，自动装饰会检测到并跳过，只是没有必要这样写。

## 手工构造的 RestTemplate

没有经过 Spring Bean 生命周期的实例需要手工接入。追加拦截器，避免覆盖已有认证、重试或业务拦截器：

```java
import com.yomahub.tlog.resttemplate.TLogRestTemplateInterceptor;
import org.springframework.web.client.RestTemplate;

RestTemplate client = new RestTemplate();
client.getInterceptors().add(new TLogRestTemplateInterceptor());
String result = client.getForObject(
        "http://127.0.0.1:18081/api/context", String.class);
```

单独使用时声明 `tlog-rest-template:2.0.0` 和应用自己的 `spring-web`。RestTemplate 本身属于 Spring，这与[纯 Java 客户端示例](/guide/examples#纯-java-客户端)的无 Spring 运行环境不同。

## RestClient 与 WebClient

| 客户端 | 自动装饰的对象 | 边界 |
| --- | --- | --- |
| RestTemplate | `RestTemplate` Bean | 方法内临时 new 的实例需手工添加 |
| RestClient | `RestClient.Builder` Bean | Spring 6.1+；在 Bean 方法内部自行创建 Builder 并立即 build，不能假设已被装饰 |
| WebClient | `WebClient.Builder` Bean | 已构造好的任意 WebClient Bean 不属于这个自动装饰点 |

Spring 6.1+ 的手工 RestClient 接入复用同一个阻塞客户端拦截器：

```java
import com.yomahub.tlog.resttemplate.TLogRestTemplateInterceptor;
import org.springframework.web.client.RestClient;

RestClient client = RestClient.builder()
        .requestInterceptor(new TLogRestTemplateInterceptor())
        .build();
```

Boot 4 拆分了客户端自动配置。请提供所需 Builder Bean，或引入对应客户端 starter；不能只引入服务端 Web starter 就假设所有 Builder 一定存在。

WebClient 的订阅上下文、线程切换和正确使用方式见[WebFlux 与 WebClient](/guide/webflux)。
