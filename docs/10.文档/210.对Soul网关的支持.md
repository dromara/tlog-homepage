# Soul 与 ShenYu 网关

TLog 2.0 保留 Soul 和 Apache ShenYu 的独立 starter。根据实际网关选择一个，不需要再叠加通用 Web starter：

| 网关 | TLog 依赖 |
| --- | --- |
| Soul | `com.yomahub:tlog-soul-spring-boot-starter:2.0.0` |
| Apache ShenYu | `com.yomahub:tlog-shenyu-spring-boot-starter:2.0.0` |

```xml
<dependency>
    <groupId>com.yomahub</groupId>
    <artifactId>tlog-shenyu-spring-boot-starter</artifactId>
    <version>2.0.0</version>
</dependency>
```

网关框架自身的版本和运行依赖由应用提供。自动配置检测相应 Handler 与 TLog 适配类后，注册转发模式的 WebFlux Filter 和插件日志切面，避免与普通 WebFlux 自动配置重复建立上下文。

## 开关与传播

```yaml
tlog:
  enabled: true
  web:
    enabled: true
    response-header: true
```

`web.enabled=false` 关闭对应网关的 Web 接入，`response-header=false` 关闭响应头回写。默认入站没有 TLog traceId 时可以复用合法 `traceparent` 中的 trace-id，具体范围见[W3C 支持边界](/guide/compatibility#w3c-与其它边界)。

2.0 使用跨 Spring 5～7 稳定的 HTTP 头读写方式，并采用 Reactor Context 隔离请求。应用中的外部线程或脱离链路的手工 subscribe 仍需显式传播，见[WebFlux 说明](/guide/webflux)。

## 验证范围

当前库验证覆盖条件装配、开关、转发和上下文行为，最小 starter 启动检查也包含 Soul/ShenYu。**本轮 107 组实际 demo 场景没有启动 Soul 或 ShenYu 的完整服务端**；其中真实网关链使用的是 Spring Cloud Gateway。

因此，应在你使用的具体网关版本和插件链上再做端到端验证，不能将最小 classpath 启动当成完整网关验收。2.0 已执行的矩阵见[兼容性说明](/guide/compatibility)。
