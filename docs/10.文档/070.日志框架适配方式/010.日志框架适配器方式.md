# 日志框架适配器方式

TLog 2.0 通过日志配置文件输出标签。框架入口先建立 TLog 上下文，再由日志 pattern、encoder、layout 或 converter 把标签写入日志。

| 日志实现 | 完整标签放在指定位置 | 在消息前追加标签 |
| --- | --- | --- |
| logback | 普通 encoder + `%X{tl}` | `AspectLogbackEncoder` 或 `AspectLogbackLayout` |
| Log4j2 | `%X{tl}`；旧 `%TX{tl}` 别名保留 | TLog 插件 `%tmsg` |
| 旧 Log4j | `%X{tl}`，SLF4J 绑定到对应实现 | `AspectLog4jPatternLayout` |

配置入口：[logback](/pages/f62a84/)、[Log4j2](/pages/8d5538/)、[旧 Log4j](/pages/a48c8e/)、[MDC](/pages/ddebe2/)。

## 选择一种标签输出方式

新接入可以先用 MDC `%X{tl}`，并设置 `tlog.mdc-enable=true`。已有 TLog encoder/layout/converter 的项目可保留配置，但应避免它和 `%X{tl}` 同时输出重复标签。

标签只会在已有 TLog 上下文的日志中出现。启动日志、未接入的后台线程或没有适配器的调用不会因为替换 encoder 就自动形成一条业务链路。

## 两种异步分别处理

业务异步指 `@Async`、线程池、CompletableFuture 等业务代码换线程，需要在提交和执行之间传播上下文。日志异步指 appender 把日志事件交给另一个线程，需要在事件入队前保留标签或 MDC。

MDC 输出可使用日志框架的事件快照；使用消息前缀适配器时，按框架页面选择 TLog 异步 appender。只安装日志异步 appender，不会自动装饰业务线程池；只包装业务线程池，也不能修复在日志消费线程临时读取上下文的错误 layout。

纯 Java 应用仍需提供日志实现与对应 SLF4J binding。实际验证范围见[兼容性](/guide/compatibility)。
