# Log4j2框架适配器

Log4j2 可以使用 MDC 输出，也保留 TLog 的消息插件。应用应提供与自己 SLF4J 版本匹配的 binding，避免同时加载 logback 和 Log4j2 两套实现。

## MDC 输出

设置 `tlog.mdc-enable=true`，使用应用原有的 `PatternLayout`：

```xml
<Configuration status="WARN">
    <Appenders>
        <Console name="CONSOLE" target="SYSTEM_OUT">
            <PatternLayout pattern="%d{HH:mm:ss.SSS} %-5level [%thread] %X{tl} %msg%n"/>
        </Console>
    </Appenders>
    <Loggers><Root level="info"><AppenderRef ref="CONSOLE"/></Root></Loggers>
</Configuration>
```

`tl` 是完整标签；`%X{tlogTraceId}` 和 `%X{tlogSpanId}` 可分别输出两个字段。

这里必须设置 `tlog.mdc-enable=true`。TLog 的 Log4j2 插件也注册了 `%m`/`%msg`，如果它被 Log4j2 选中、又没开启这个开关，消息前会再拼接一份标签。

## 保留消息前缀插件

已有项目可使用 TLog 插件的明确别名 `%tm`、`%tmsg` 或 `%tmessage`，例如：

```xml
<PatternLayout pattern="%d{HH:mm:ss.SSS} %-5level [%thread] %logger{36} - %tmsg%n"/>
```

这种写法将标签放在消息前，应保持 `tlog.mdc-enable` 未启用，并且不要再重复输出 `%X{tl}`。不要依靠 Maven 依赖顺序去覆盖原生 `%m`/`%msg` 的插件选择。

打包时要保留 TLog jar 的 Log4j2 插件元数据。自行制作 shaded jar 时，应按日志框架的要求合并插件资源；出现无法识别 `%tmsg` 时先检查插件发现和日志启动状态。

## 异步 appender

MDC 字段在业务线程创建日志事件时保存。普通 Log4j2 Async appender 可以输出这个快照：

```xml
<Async name="ASYNC">
    <AppenderRef ref="CONSOLE"/>
</Async>
```

将 `ASYNC` 放入 `Appenders`，并让 Root 引用它。队列和 AsyncLogger 所需的其它依赖按应用自身的 Log4j2 配置管理。

不需要为了这个异步 appender 示例设置 `log4j2.isThreadContextMapInheritable=true`。线程创建时的继承也不能代替线程池按任务传播；业务异步使用[自动装饰或 TLogExecutors](/pages/a69e1d/)。
