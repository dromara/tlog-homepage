# 自定义TraceId生成器

TLog 默认提供雪花 ID 生成器。需要自定义算法时，继承抽象类 `TLogIdGenerator`，实现 `generateTraceId()`。

## Spring Boot：优先声明 Bean

```java
import com.yomahub.tlog.id.TLogIdGenerator;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import java.util.UUID;

@Configuration
public class TraceIdConfiguration {
    @Bean
    public TLogIdGenerator traceIdGenerator() {
        return new TLogIdGenerator() {
            @Override
            public String generateTraceId() {
                return UUID.randomUUID().toString().replace("-", "");
            }
        };
    }
}
```

容器中有唯一候选时自动采用；存在多个候选时可使用 `@Primary` 指定。Bean 实例的优先级高于全类名配置。生成器只在入口没有可复用 traceId 时调用，不会覆盖合法的上游 TLog 头或启用状态下可复用的 W3C trace-id。

## 保留的全类名配置

```properties
tlog.id-generator=com.example.trace.CustomTraceIdGenerator
```

这个类必须继承 `TLogIdGenerator`。2.0 会在 Spring 上下文已初始化后通过容器创建实例，因此旧配置形式也支持依赖注入；加载失败会保留原因，便于定位。

不要用 `System.nanoTime()` 作为跨进程唯一 ID 算法：它不是全局唯一来源。选择适合你的部署规模和冲突要求的生成方式。

## extData 与并发

需要扩展数据时，在子类中读取 `getExtData()`。例如网关可提供当前 exchange，具体键和数据类型应以调用入口为准。

内部入口已统一使用 `generate(Map)`。旧子类受保护的 `extData` 字段保留，并在该方法中进行串行保护和恢复。应用代码应将两步旧写法：

```java
// 两次独立调用，无法为并发访问提供原子性
idGenerator.withExtData(data).generateTraceId();
```

改为：

```java
String traceId = idGenerator.generate(data);
```

## 纯 Java

通过 `TLogIdGeneratorLoader.setIdGenerator(instance)` 安装生成器，通过 `TLogRuntime.setAppName(...)` 设置应用名。主动入口还需建立并清理 TLog 上下文，见[纯 Java 可运行示例](/guide/examples#纯-java-客户端)。
