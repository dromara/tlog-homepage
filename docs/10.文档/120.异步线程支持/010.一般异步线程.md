# 一般异步线程

TLog 的部分上下文使用可继承 ThreadLocal，新线程可能在创建时继承父线程的值；这不能保证普通 MDC 一起传播，也不能代表后续复用线程的每次任务都继承正确请求。2.0 建议明确包装任务。

```java
import com.yomahub.tlog.core.thread.TLogExecutors;

Runnable task = TLogExecutors.wrap(() -> log.info("执行异步业务"));
Thread thread = new Thread(task, "business-once");
thread.start();
```

在调用 `wrap` 时捕获当前 TLog 和 MDC，执行任务时安装，执行结束后恢复该线程原有状态。应在所属请求仍有效时创建包装任务，不要把同一个包装实例重复用作其它请求的任务。

如果任务并不属于当前请求，例如独立后台循环，应在它自己的任务入口建立与清理 trace；不要长时间保留一个请求的上下文。

## 旧 API

`TLogInheritableTask` 仍可使用，2.0 已移除对 JDK 内部线程字段的反射：

```java
new TLogInheritableTask() {
    @Override
    public void runTask() {
        log.info("执行异步业务");
    }
}.start();
```

该类在构造时捕获上下文。线程池与 CompletableFuture 请继续阅读[线程池支持](/pages/a69e1d/)，响应式流使用[Reactor Context](/guide/webflux)。
