# 线程池

线程池会复用工作线程，不能依赖新建线程时的继承来追踪每次请求。2.0 分别处理 Spring 管理执行器与应用自己创建的执行器。

## Spring 管理的执行器

`tlog.async.enabled=true` 默认开启。TLog 在 Bean 初始化前装饰 `ThreadPoolTaskExecutor` 和 `SimpleAsyncTaskExecutor`，原有 TaskDecorator 会组合保留：

```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.annotation.EnableAsync;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;

@Configuration
@EnableAsync
public class AsyncConfiguration {
    @Bean("businessExecutor")
    public ThreadPoolTaskExecutor businessExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(4);
        executor.setMaxPoolSize(8);
        executor.setQueueCapacity(100);
        executor.setThreadNamePrefix("business-");
        return executor;
    }
}
```

在另一个 Spring Bean 的方法上使用 `@Async("businessExecutor")`，并通过代理调用。TLog 不会替应用启用 `@EnableAsync` 或修复 Spring 自调用绕过代理的情况。

用户 TaskDecorator 应在 Bean 初始化前设置；初始化后再次调用 setter 会替换已经安装的组合装饰器。一个普通 `ExecutorService` 即使注册为 Bean，也不属于上述两个自动装饰类型，应显式包装。

## 自建执行器

```java
import com.yomahub.tlog.core.thread.TLogExecutors;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

ExecutorService pool = TLogExecutors.wrap(Executors.newFixedThreadPool(5));
try {
    pool.submit(() -> log.info("线程池内的业务日志")).get();
} finally {
    pool.shutdown();
}
```

`Executor`、`ExecutorService`、`ScheduledExecutorService` 的包装都传播 TLog 和 MDC。`submit`、`execute`、`invokeAll`、`invokeAny` 及调度入口采用相同语义；任务结束或抛异常后恢复工作线程原有状态。

## CompletableFuture

```java
CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
    log.info("CompletableFuture 内的日志");
    return "done";
}, pool);
```

这里的 `pool` 必须是包装后的执行器。省略执行器时使用的默认异步线程池，不会因为加入 TLog 依赖就自动按任务透传。

## 周期任务与旧代码

周期调度会反复使用提交时捕获的上下文。需要每轮独立 trace 时，应在每轮任务入口创建和清理，而不是在某个 HTTP 请求里注册一个永久携带该请求 ID 的周期任务。

旧 `TLogInheritableTask` 仍可提交到线程池；它在对象构造时捕获上下文。新代码通常直接包装执行器更清楚。只使用 TTL 原生执行器包装时，不能额外假定普通日志 MDC 也已复制；TLogExecutors 同时处理两者。

关闭 `tlog.async.enabled` 会同时关闭 Spring 执行器的自动装饰和 MVC 异步请求（Callable / WebAsyncTask）的上下文传播，但不撤销你显式调用的 `TLogExecutors.wrap`。更多开关见[配置参考](/guide/configuration)。
