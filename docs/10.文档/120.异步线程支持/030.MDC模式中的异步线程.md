# MDC模式中的异步线程

排查异步日志缺标签时，先判断是哪一种线程切换。

| 场景 | 需要保留什么 | 2.0 的接入 |
| --- | --- | --- |
| `@Async` / Spring 执行器 | 任务提交者的 TLog 和 MDC | 自动装饰受支持的执行器 Bean |
| 自建线程池 / CompletableFuture | 每次任务提交时的 TLog 和 MDC | `TLogExecutors.wrap` |
| 原生新线程 | 包装时的 TLog 和 MDC | 包装 Runnable 或使用 TLogInheritableTask |
| 日志异步 appender | 业务线程创建日志事件时的标签 | 使用事件 MDC 快照或 TLog 异步 appender |
| Reactor 信号回调 | 当前订阅的请求上下文 | [Reactor Context 桥接](/guide/webflux) |

## 包装任务

```java
Runnable task = TLogExecutors.wrap(() -> {
    log.info("当前 traceId={}", MDC.get("tlogTraceId"));
});
executor.execute(task);
```

`task` 在包装时捕获 MDC，执行后恢复工作线程原有 MDC。包装的 ExecutorService 和 ScheduledExecutorService 也有相同行为。没有入口上下文时，包装不会凭空生成 traceId。

## 保留 TLogInheritableTask

```java
public class BusinessTask extends TLogInheritableTask {
    @Override
    public void runTask() {
        log.info("处理异步业务");
    }
}
```

在当前请求作用域创建 `new BusinessTask()`，再调用 `start()` 或提交到执行器。该类构造时捕获上下文，不适合把同一个实例复用到不同请求。

## logback listener 的作用

`TLogLogbackTTLMdcListener` 可以安装 TTL MDC adapter，是旧接入方式的兼容选项。它不等于线程池每次提交都自动装饰。使用 2.0 的 Spring 自动装饰或 TLogExecutors 时，已经显式处理 MDC，不要求为这些路径额外安装 listener。

不要用 `log4j2.isThreadContextMapInheritable` 或一次新线程继承来证明线程池透传正确。应先预热线程池，再交错提交不同 traceId 的任务，并检查任务结束后的线程状态；可运行验证见[示例工程](/guide/examples)。
