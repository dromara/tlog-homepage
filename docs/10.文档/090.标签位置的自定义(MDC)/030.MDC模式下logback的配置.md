# MDC模式下logback的配置

2.0 的入口会直接写入 MDC。采用下面的普通 encoder 即可输出完整标签，不要求额外安装 MDC listener：

```xml
<configuration>
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{HH:mm:ss.SSS} %-5level %X{tl} [%thread] %msg%n</pattern>
        </encoder>
    </appender>
    <root level="INFO"><appender-ref ref="CONSOLE"/></root>
</configuration>
```

可设置 `tlog.mdc-enable=true`，防止应用保留的 TLog 消息转换器重复输出标签。也可以直接输出 `%X{tlogTraceId}`、`%X{tlogSpanId}`。

## 可选 TTL MDC listener

旧项目依赖 TTL MDC adapter 时，可保留：

```xml
<contextListener class="com.yomahub.tlog.core.enhance.logback.TLogLogbackTTLMdcListener"/>
```

把它放在 `configuration` 内。2.0 已适配 SLF4J 1.7/2.x 的字段差异和现代 logback 的 LoggerContext MDC 读取路径。该 listener 会安装进程中的 MDC adapter，并将标签输出模式设置为 MDC，因此 pattern 必须包含相应字段。

新 Spring 执行器自动装饰和 `TLogExecutors.wrap` 已会显式复制 MDC，通常不需要再为了这些路径安装 listener。listener 也不会让任意未包装线程池自动按每次任务捕获调用者的 MDC。

## 异步 appender

使用普通 logback AsyncAppender 时，pattern 继续使用 `%X{tl}`，读取日志事件已保存的 MDC。不要在异步日志消费线程读取业务 ThreadLocal 来重建标签。

业务 `@Async`、外部线程池、CompletableFuture 的处理见[MDC 异步](/pages/348797/)。
