# 对servlet的支持

TLog 2.0 的 Servlet 入口使用 Filter 建立上下文，在请求结束或异常时清理。Spring Boot 应用由 starter 自动注册；传统 Servlet 容器可以在 `web.xml` 手工配置。

## Spring Boot 自动注册

引入 `tlog-web-spring-boot-starter:2.0.0`，并保留应用自己的 Web starter。TLog 根据当前 Spring 代际选择 Filter：

| 应用环境 | 使用的实现 |
| --- | --- |
| Spring 5 / Boot 2，javax Servlet | `com.yomahub.tlog.web.filter.TLogServletFilter` |
| Spring 6/7 / Boot 3/4，jakarta Servlet | `com.yomahub.tlog.web.filter.TLogJakartaServletFilter` |

同一套 TLog 坐标覆盖两种命名空间，不需要 `-jakarta` starter。自动配置覆盖 REQUEST、ASYNC、ERROR；请求属性保存首次建立的上下文，异步重派发和错误处理沿用同一 trace/span。MVC Callable 的内部执行器也有生命周期拦截器补充传播。

默认顺序为 `Integer.MIN_VALUE + 1`，在 Boot 字符编码过滤器之后、常规安全过滤器之前。自定义 `tlog.web.order` 时仍应让字符编码过滤器先执行，避免日志读取表单参数时提前使用错误编码。

```yaml
tlog:
  web:
    enabled: true
    response-header: true
```

`response-header=false` 关闭 `tlogTraceId` 响应头回写。Boot 已自动注册时，不要再添加同一 Filter 或旧 MVC 拦截器。

## 非 Boot Servlet 容器

声明 `tlog-webroot:2.0.0`，提供与容器匹配的 Servlet API 及所需 Spring 运行库。这里不是“完全没有 Spring jar”的客户端场景。

javax 容器配置片段：

```xml
<filter>
    <filter-name>tlog</filter-name>
    <filter-class>com.yomahub.tlog.web.filter.TLogServletFilter</filter-class>
    <async-supported>true</async-supported>
</filter>
<filter-mapping>
    <filter-name>tlog</filter-name>
    <url-pattern>/*</url-pattern>
    <dispatcher>REQUEST</dispatcher>
    <dispatcher>ASYNC</dispatcher>
    <dispatcher>ERROR</dispatcher>
</filter-mapping>
```

jakarta 容器将 `filter-class` 改为 `com.yomahub.tlog.web.filter.TLogJakartaServletFilter`，并使用容器支持的 Jakarta `web.xml` schema。相关 Servlet 和过滤器链也必须允许异步处理；TLog 不能替其它过滤器启用 asyncSupported。

手工注册时，把字符编码过滤器放在 TLog 之前。传统 Spring MVC 的 javax 拦截器仍保留，但不能直接用于 Spring 6/7；现代容器使用 Jakarta Filter。版本与实际验证范围见[兼容性说明](/guide/compatibility)。
